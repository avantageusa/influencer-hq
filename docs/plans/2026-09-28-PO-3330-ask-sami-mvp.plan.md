# PO-3330 (FR-19) — "Ask Sami" MVP, text-only

**Epic:** https://avantageusa.atlassian.net/browse/PO-3062
**Drafted by:** Claude Code (Sonnet 5)

## Problem

FR-19 wants a visitor to be able to interrupt Sami's fixed script and ask a
real question. Two separate things were blocking it: Gary's `/message`
endpoint only ever returned held-content boilerplate (fixed 2026-09-28,
independent of this change), and even once it returns a real answer, nothing
in this codebase's frontend calls that endpoint at all — it was fully wired
on the backend (`inc/gary-proxy.php`) but never exposed to a visitor.

## Approach

Smallest useful slice: a button + question box, wired directly to the
now-working `/message` route, showing the answer as text. Reuses the same
Gary session `start()` already opens and keeps alive for the entire
registration flow — no new session lifecycle to manage.

## Alternatives considered

- **Make Sami speak the answer live (voiced, lip-synced).** The real target
  experience, but `say.audio`/`say.video` on `/message`'s response require
  infrastructure that doesn't exist yet (see Notes) — building that first
  would have blocked shipping the actually-valuable part (a real answer,
  readable immediately) behind unrelated plumbing work.
- **Open a fresh Gary session per question** instead of reusing
  `garySessionId`. Rejected — the session already stays open for the whole
  flow (only closed on error or at registration completion), reusing it is
  simpler and avoids Gary-side session churn for no benefit.
- **Gate the whole flow to English instead of hiding just the Ask Sami
  entry point.** Rejected — non-English visitors still get everything else
  (translated captions, translated clips); only the free-text Q&A itself is
  English-only per Gary, so only that entry point is hidden.

## Blast radius

- `inc/gary-proxy.php`: one added field (`want`) on an existing request,
  no new route.
- `js/aicoach-coach-flow.js`: one new self-contained function
  (`buildAskSami()`), one new URL helper, a few lines in `selectLocale()`
  and `start()` to gate/enable it. Nothing else in the sequence loop,
  `SCREENS`, or the pre-rendered-clip logic is touched.
- `page-home-aicoach.php`: CSS only, new `.aicoach-ask-*` rules alongside
  the existing `.aicoach-lang-*` block — no markup changes (same
  JS-builds-the-DOM pattern as the language selector).

## Notes

**Voicing the answer is a real follow-up, not done here.** Live-testing
turned up that `say.audio` on a real generated answer is not a playable URL
— it's an object (`{ id, url, format, expires_at, ... }`) whose `url` (e.g.
`/coach/v1/audio/{id}`) is a path on Gary's own API host, signed the same
way every other `ihq_coach_request()` call is. The visitor's browser can't
fetch it directly, and nothing in `inc/gary-proxy.php` proxies it live today
— `ihq_coach_download()` is a build-time, stream-to-disk tool the prerender
scripts use, not a REST route. An initial version of this change assumed
`say.audio` was a plain URL and tried to play it directly; caught live
(silent 404, no crash, since the fetch was wrapped) and removed rather than
shipped. Making Sami actually speak an Ask Sami answer needs a new proxy
route (stream Gary's `/coach/v1/audio/{id}` back through our own REST
endpoint) at minimum, and reconnecting/redirecting the live avatar for a
lip-synced version is bigger still — both left for a follow-up ticket.

**Silent-resume visitors never get Ask Sami**, same as they never get the
live avatar — PO-3102's resume path deliberately never calls `start()` for a
visitor resumed past the intro ("no live Gary session" by existing design),
so `garySessionId` stays null and the button stays disabled. Consistent
with the rest of the page's degrade pattern, not a new gap.

**The main sequence keeps advancing in the background while the question
panel is open** — flagged by CodeRabbit on PR #59, confirmed real. Fixed in
PO-3346 (2026-09-29): `waitForReadOrSkip()` and `playPrerenderedClip()`'s
60s safety cap now run through `createPausableTimeout()`, and
`openPanel()`/`closePanel()` call `pauseSequenceTimers()` /
`resumeSequenceTimers()`. The live intro's `waitForSpeechOrSkip()` is
deliberately still not covered — pausing local video rendering doesn't
pause the actual live Gary/Anam conversation server-side, a genuinely
different, harder problem than pausing a fixed dwell or a local clip's
safety cap. See PO-3346 for that scope boundary.
